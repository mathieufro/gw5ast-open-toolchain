## 1. The reconciliation

`fse_create_ae350()` now consumes `read_ae350_soc_ins` / `Ae350SocOuts` as
`P2.T08b` measured them, and the band filter `P2.T07` used is **removed**: a
live record is a tap wherever it lands, and only a sentinel slot leaves a bit
unmapped.

| | `P2.T07` | `P2.T10` |
|---|---|---|
| bits bound | 722 / 911 | **884 / 911** |
| placeholders | 189 | **27** |
| mismatches vs `wire-map-138c.json` | — | **0** |

The 27 are exactly the sentinel records of the two tables, plus the one output
bit past the end of `Ae350SocIns` inside the run; every one of them is an
output. 884 is the number `wire-map-138c.json` itself records; the two are
derived by different code from the same tables and agree bit for bit
(`$OTC/tools/tests/test_ae350_chipdb_reconciliation.py`).

### The anchor moved to `(0, 159)`

`P2.T07` anchored at `(0, 145)` as "the row-0 tile at the first tapped column",
under the split-band reading of the stale `Ae350SocIns` base. That reading is
refuted: column 145 is not tapped, is not driven, and shows no changed bit in
die row 0 of run `p2t26-tilewires`. The rationale therefore no longer holds and
the anchor follows the measurement to the first column of the measured band,
`(0, 159)`. There is no band constant at all: `_AE350_SOC_BAND_COLS` was
removed at the Phase-2 gestalt close, because a column bound would have to be
either the anchor's own column or the span of the port taps and neither
describes the block — `Ae350SocOuts` also names columns 22, 23 and 87, three
real clock-spine taps any band filter would drop.
`test_ae350_anchor_is_the_measured_one_and_nothing_filters_by_column` asserts
the constant stays gone; `portmap-138c.md` states the three spans it was
conflating.

## 4. The open-flow run, and where it stops

Design: run `p2t26-tilewires`'s own `top.v` — all 149 ports, every non-clock
input bit driven by its own flop of a 410-bit shift chain, every output bit
captured by its own flop. All six clock ports are driven by the ordinary fabric

## 5. The residual class, precisely

**One class, structural, and it is not a defect in the map.**

*(Refuted by `P2.T23` — see `route-138c.md` §1. Kept as the record of the
reading that produced it; the per-direction counts here are the pre-correction
ones.)*

Every one of the 867 bound ports names a *fabric tile's own* wire, in one of 27
row-0 tiles:

| direction | taps | distinct tiles | wire classes |
|---|---|---|---|
| inputs | 398 | 20 | `Q` 134, `F` 132, `OF` 132 |
| outputs | 469 | 23 | `B` 101, `D` 100, `A` 97, `C` 96, `OF` 19, `F` 18, `Q` 16, `CE` 13, `CLK` 7, `LSR` 2 |

An input tap is a tile *output* (`F` = a LUT's output, `Q` = a DFF's, `OF` = the
slice's registered output), so the only cell that can drive it is the LUT or
DFF at that index **in that tile**. An output tap is a tile *input* (`A`-`D` are
one LUT's inputs), so the only cell that can consume it is the LUT at that index
in that tile. Each of the 867 nets therefore has exactly **one** legal fabric
endpoint bel, and 264 of the 398 input taps name a `F`/`OF` wire rather than a
flop output, so the vendor's netlist decomposition — a buffer cell per tap —
is part of the constraint too.

nextpnr's placer has no mechanism for "this cell must be placed at the bel that
drives this hard block's tap". It places the 905 flops by wirelength, the router
then meets a sink reachable only from a bel that is empty, and stops. The
warning list is uniform: the failing arcs are AE350 port nets, never fabric
nets.

**What would close it**, in increasing order of cost:

1. emit the 867 placement constraints from the wire map — mechanical, and it
   makes `E0` reachable on this vehicle without any placer change;
2. teach the gowin uarch a cluster/"tap" constraint so the placer derives them
   (the upstreamable form, and what `P2.T16` should become);
3. reduce the vehicle to the `Emb_TCM` subset (`P2.T20`), where the tap count
   is small enough that (1) is trivial.

None of the three is a change to the port map, which is what `P2.T10` set out
to prove: the map is right, and the flow stops one layer above it.
