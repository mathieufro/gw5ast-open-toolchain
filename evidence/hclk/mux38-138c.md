# GW5AST-138C: the central clock mux, the six-block escape map, and the first
# CLKDIV that routes — P1.T08d

apicula `clocking/gw5a-hclk-6block`. Oracle: Gowin IDE **1.9.12.03 Standard,
licensed**. Closes `D100`; supersedes `backbone-138c.md` §2's "twenty of the
twenty-four wires are NOT MEASURED".

## Verdict, up front

A `CLKDIV` output now reaches the global clock network through the open flow.
`nextpnr-himbaechel` exits **0** on the P1.T11 design, its log says
`'div_clk' net was routed using global resources only`, `gowin_pack` writes a
`top.fs`, and with the CLKDIV pinned to the vendor's own site the HCLK-scoped
**E1 is `cells=0 attrs=0 conns=0`** against the vendor bitstream.

Three defects had to be fixed to get there, each measured, none guessed:
the central clock mux's escape wires were discarded by `fse_clock_pips_138`;
the HCLK→clock hop had no node; and every 138C HCLK wire was called
`HCLK_UNK<n>`, so the CLKDIV bels' own port wires named nothing.

## 1. The table-38 model (MEASURED, `.fse` + bitstreams)

`.fse` wire table 38 (`_wire_tables['CLOCK_MUX']`) is the device's **central
clock mux**. Eighteen cells carry it; two matter:

| cell | fse ttyp | table-38 rows | SPINE destinations | source bands |
|---|---|---|---|---|
| (54,88) | 80 | 1672 | SPINE16..21 | 81..112, 131..138, 180..233, 235, 236 |
| (54,93) | 85 | 1259 | SPINE8..13 | 81..112, 131..138, 180..211, 234 |

(the other sixteen — (54,89) (54,90) (54,92) and the thirteen 16-row cells in
column 90 — carry table 38 too and are read by the same code path.)

`fse_clock_pips_138` **does** read table 38 (`chipdb.py`, the third loop);
what it did not do is keep the sources that matter. Two `continue` rules,
`srcid in range(105, 129)` ("unknown wires") and `srcid in range(164, 237)`
("longwires"), discarded **every wire an HCLK block escapes on** — the
measured 105..112 and 220..227 fall inside them. That, not a missing table,
is what `D100` should have said.

The fix is data-driven, not a widened range: `gw5_hclk_clk_wire_ids(device)`
returns exactly the wire ids in the device's measured `_gw5a_hclk_to_clk`
table, and only those are exempted from the two filters. A device with no
measured table (the GW5A-25A, every pre-5A part) keeps the filters unchanged.
Result on the built chipdb: **416** escape pips appear — 280 at (54,88), 136
at (54,93) — where there were 0.

## 2. The placement handle P1.T08c lacked

`SUG1018-1.7E Arora V Design Physical Constraints User Guide` §2.9 "HCLK
Primitive Constraints" (shipped at `$GOWINHOME/IDE/doc/EN/`): a CLKDIV is
pinned with

```
INS_LOC "div0" BOTTOMSIDE[4];
```

Table 2-2, row `GW5A(S)(T)-138`: `{LEFT,RIGHT,BOTTOM}SIDE[0~7]`, no TOPSIDE.
Corroborated in `IDE/lib/libgowin.dylib` (`INS_LOC`, `INS_CLKDIV`,
`placeClkdivFlag`, the four `*SIDE[` templates) and in the floorplanner's
closed pick-list. Twenty-four positions = six blocks × four lanes.

**The side/index convention, MEASURED, not assumed** (each run decoded for the
block cell it lit):

| INS_LOC | HCLK block | block cell |
|---|---|---|
| `LEFTSIDE[0..3]` | 0 | (27,0) |
| `LEFTSIDE[4..7]` | 2 | (81,0) |
| `RIGHTSIDE[0..3]` | 1 | (27,181) |
| `RIGHTSIDE[4..7]` | 3 | (81,181) |
| `BOTTOMSIDE[0..3]` | 4 | (108,64) |
| `BOTTOMSIDE[4..7]` | 5 | (108,117) |

## 3. The six-block map (24 + 3 vendor runs)

One CLKDIV per run, `CLKOUT` clocking a counter so the output must escape.
Each `.fs` is decoded twice by `evidence/hclk/probe_clkmux.py`: the block
cell's lit table-48 `HCLK_MUX_BETA0i <= L2HCLK0i` row gives **(block, lane)**,
the central mux's lit table-38 row gives **the clock wire**.

| block | cell | lane 0 | lane 1 | lane 2 | lane 3 |
|---|---|---|---|---|---|
| 2 | (81,0)    | **105** | **106** | **220** | **221** |
| 4 | (108,64)  | **107** | **108** | **222** | **223** |
| 5 | (108,117) | **109** | **110** | **224** | **225** |
| 3 | (81,181)  | **111** | **112** | **226** | **227** |
| 0 | (27,0)    | — | — | — | — |
| 1 | (27,181)  | — | — | — | — |

Two wires per block from each of two disjoint bands, 105..112 and 220..227,
stepping by two per block in the order **2, 4, 5, 3** — every one of the four
bottom-half blocks. Block 5's row reproduces `backbone-138c.md`'s staircase
(`{0:109, 1:110, 2:224, 3:225}`) from four *independent* runs, which
cross-validates both instruments.

**Blocks 0 and 1 are absent, not guessed.** All eight of their lanes were run.
Every one lights exactly one central-mux row and it is always the same one —
`SPINE16 <= BRPLL0CLK0` (clknames 101, `SPINE21` for lane 3) — so 101 cannot
be a per-lane bijection. A confirming staircase of **2, 3 and 4** CLKDIVs all
pinned inside block 0 (`LEFTSIDE[0..3]`) still lights that single row, so the
two TOP-half blocks do not surface per-lane on the central clock mux at all
and their escape mechanism is unidentified. A design placed in block 0 or 1
therefore still has no modelled clock escape; `test_hclk_to_clk_mapping_six_blocks_measured`
asserts their absence so it cannot be quietly filled in.

## 4. What the chipdb now does

1. **`gw5_hclk_clk_wire_ids` + the relaxed table-38 filters** (§1) — the mux
   pips exist, with their fuses.
2. **`gw5_make_hclk_to_clk_nodes`** — the HCLK-block → clock-mux hop carries no
   fuse (`backbone-138c.md` §1), so it is a Himbaechel **node**, not a pip:
   each `CLKDIV_O<b><i>` wire is joined to the clock wire the table above gives
   it, which `fse_create_5a138_clocks` has already created as a node in the
   bridge cells. Called at the end of `gw5_add_hclk_bels`, a no-op for a device
   with no measured table.
3. **`wirenames.hclknames_5ast138c` now names all six blocks.** This was the
   load-bearing one. The table was a copy of `clknames_5ast138c` with
   `HCLK_UNK<n>` written over 2..700 only, so *every* 138C HCLK wire outside
   that band kept a clock-network name, and blocks 4/5 (ids 748.. and 935..)
   collided with the `LWSPINE*` band at 1001..1048. Meanwhile
   `gw5_add_hclk_bels` builds every CLKDIV/CLKDIV2 port wire from an f-string
   literal (`HCLK_MUX_ALPHA41`, `CLKDIV_I41`, …). Those literals named wires no
   table-48 pip ever touched: **every CLKDIV input was an island**, which is
   the `Failed to find a route for arc 0 of net clk_IBUF_I_O` that survived the
   output fix. The 25A's structural names are carried across for six blocks at
   the measured 187 stride — justified by P1.T08b (same walk, same per-block
   count on all six) and by this task's own decode, which found the vendor
   lighting `L2HCLK<b><i> -> HCLK_MUX_BETA<b><i> -> HCLK_BUF_BI<b><i> ->
   HCLK_BUF_BO<b><i> -> HCLK_MUX_ALPHA<b><i>` in both (108,117) and (27,0),
   exactly the 25A's shape. Append-only: `HCLK_TO_GCLK*` / `HCLK_GCLK*` keep
   the names the 138C table sets for itself, and `hclknames_5a25a` is read,
   never written.
4. **The 138C's own `HCLK_TO_GCLK*` / `HCLK_GCLK*` literals were four-block
   too** -- ids 25/27/28/29 and 123..130 plus 187, 374, 561, i.e. one
   `gw5_hclk_wire_offset` per block, stopping at block 3. Generated for all six
   now; blocks 0-3 keep byte-identical names. Without it blocks 4 and 5 came out
   four HCLK nodes short of the other four and
   `test_hclk_pip_nodes_equal_across_blocks` (P1.T08b) failed.
5. **`gowin_pack`: `get_CLKDIV_fuses` / `get_CLKDIV2_fuses` moved from
   `GW5A_25A` up to `GW5A`.** GW5AT-60B and GW5AST-138C inherited the pre-5A
   implementation and died on the first CLKDIV in `get_hclk_sections` — whose
   stray `import ipdb; ipdb.set_trace()` raised `ModuleNotFoundError` instead
   of its own exception. The debugger line is deleted; the two methods moved
   unchanged, so `GW5A_25A` inherits exactly what it used to define.

(The two `.fs` in §5 are byte-identical before and after item 4, so it is a
naming repair, not a bitstream change.)

## 6. E0 / E1, scoped to the HCLK block tiles + the clock-mux cells

Scope = the six HCLK block cells + (54,88) and (54,93);
`evidence/hclk/e0_hclk_scope.py`. Vendor side = the P1.T11 bitstream
`3d36f0aa…` (same design, `-use_sspi_as_gpio 1`).

**E1 — placement pinned to the vendor's site (X117Y108/CLKDIV_0):**

```
vendor in-scope cells: [(117, 108, 0, 'CLKDIV_'), (117, 108, 5, 'HCLK')]
open   in-scope cells: [(117, 108, 0, 'CLKDIV_'), (117, 108, 5, 'HCLK')]
DIFF_COUNT cells=0 attrs=0 conns=0 pips=2019420
FIRST_DIFF None
PER_TILE {}
RESIDUAL_UNEXPLAINED bits=17 tiles={(117, 108): 17}
```

**E0 — placement free (nextpnr picks block 4, the vendor block 5):**

```
DIFF_COUNT cells=4 attrs=8 conns=0 pips=2019890
FIRST_DIFF tile (117,108) bel 0: cell vendor=CLKDIV_ open=<absent>
PER_TILE {'(64,108)': {cells 2, attrs 4}, '(117,108)': {cells 2, attrs 4}}
RESIDUAL_UNEXPLAINED bits=36 tiles={(64,108): 20, (88,54): 1, (117,108): 15}
```

The E0 difference is **entirely the placement**: the same CLKDIV_ + HCLK pair
at two different blocks, counted twice by key. Pinning it removes all of it.

**The 17 E1 residual bits are attributed, not waved through.** They are all in
the HCLK block tile, none of them is a fuse of any `.fse` table-48 row and none
belongs to the tile's `HCLK` shortval table, and `equiv.split_tile_bits`
classifies **17/17 as `net_route`, leftover 0** — the two flows picked
different pips *inside* the block (7 bits vendor-only, 10 open-only) for the
CLKDIV's input path. Routing is never a verdict term (`D32`), so E1 is clean:
`cells=0 attrs=0 conns=0`. The `pips` field is the usual whole-design
statistic, not a scoped number.

## 10. Recorded, not fixed

1. **Blocks 0 and 1 have no modelled clock escape** (§3). Eleven of the 27
   runs went at it and the answer was negative each time; identifying the
   top-half mechanism needs an instrument this task did not have.
2. **`get_hclk_sections`'s `^_HCLK([0,1])_SECT([0,1])$` is still pre-5A-only.**
   Correct now that the GW5A path no longer reaches it, but the character class
   `[0,1]` also matches a comma — an upstream typo left alone.
3. The **inter-HCLK crossbar defaults** are still 4-block literals
   (`network-138c.md` item 2); untouched here.
